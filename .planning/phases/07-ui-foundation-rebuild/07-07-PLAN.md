   - At the very top of the function, ALWAYS cancel both pending tasks and clear the handles:
     ```swift
     playingOutTask?.cancel()
     playingOutTask = nil
     showingResultTask?.cancel()
     showingResultTask = nil
     ```
   - For the `.playingOut` branch, assign the new Task to `playingOutTask`:
     ```swift
     playingOutTask = Task {
         try? await Task.sleep(nanoseconds: 300_000_000)
         guard !Task.isCancelled else { return }
         await MainActor.run {
             guard viewModel.phase == .playingOut else { return }
             viewModel.playOutDealer()
         }
     }
     ```
   - For the `.showingResult` branch, assign the new Task to `showingResultTask`:
     ```swift
     showingResultTask = Task {
         try? await Task.sleep(nanoseconds: 1_000_000_000)
         guard !Task.isCancelled else { return }
         await MainActor.run {
             guard viewModel.phase == .showingResult else { return }
             viewModel.advanceToNextHand()
             viewModel.dealNewHand()
             viewModel.feedbackState = nil
         }
     }
     ```
   - The phase guards inside each Task closure prevent a stale Task that survived cancellation (e.g. during the await suspension) from mutating state for the wrong phase.

3. Do NOT change the `.onChange(of: viewModel.phase)` modifier on line 64 — handlePhaseChange now handles cancellation itself, so onChange continues to call it as-is.
