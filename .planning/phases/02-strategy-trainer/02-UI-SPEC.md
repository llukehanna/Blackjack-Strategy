# Phase 2 — UI Design Contract

> Visual and interaction contract for the Strategy Trainer MVP. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native SwiftUI) |
| Preset | not applicable |
| Component library | SwiftUI built-in controls |
| Icon library | SF Symbols (Apple system icons) |
| Font | SF Pro (iOS system font, automatic with SwiftUI `.font()` modifiers) |

**Rationale:** This is a native iOS app. SwiftUI provides the full component set, SF Symbols provides icons, and SF Pro is the system font. No third-party UI libraries needed.

---

## Spacing Scale

SwiftUI uses points (pt), not pixels. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label gaps, suit symbol kerning |
| sm | 8pt | Card-to-card spacing within a hand, compact inline padding |
| md | 16pt | Default element spacing, action button gaps, section padding |
| lg | 24pt | Spacing between dealer hand / player hand / action bar zones |
| xl | 32pt | Top-level layout margins (safe area insets) |
| 2xl | 48pt | Major section breaks (session summary section gaps) |

Exceptions:
- Card dimensions: 56pt wide x 80pt tall (per RESEARCH.md CardView spec). Not on the spacing scale but fixed component size.
- Action buttons: minimum 44pt touch target height (Apple HIG requirement).
- Stats bar: 8pt vertical padding, keeping it compact per D-09.

---

## Typography

All sizes use SwiftUI Dynamic Type text styles. Values shown are the default (Large) size class. Dynamic Type automatically scales for accessibility.

| Role | SwiftUI Style | Default Size | Weight | Line Height |
|------|---------------|-------------|--------|-------------|
| Body | `.body` | 17pt | regular (400) | 1.29 (22pt) |
| Label / Stats | `.subheadline` | 15pt | regular (400) | 1.33 (20pt) |
| Heading | `.title2` | 22pt | bold (700) | 1.27 (28pt) |
| Card rank+suit | `.title2.monospaced()` | 22pt | bold (700) | 1.27 (28pt) |

**Weight constraint:** Two weights only across the app:
- **Regular (400):** Body text, labels, stats bar, form fields, mistake log entries
- **Bold (700):** Headings, card labels, feedback overlay text, action button labels, accuracy percentage

**Monospaced exception:** Card labels (`A{heart}`, `10{club}`) use `.monospaced()` for consistent card width alignment. This is a font variant, not a separate weight.

## Color

The app uses SwiftUI semantic colors exclusively. This ensures automatic light/dark mode support without maintaining two palettes. The aesthetic is "clean, premium, slightly analytical" per PROJECT.md.

| Role | SwiftUI Token | Light Mode Hex (reference) | Usage |
|------|--------------|---------------------------|-------|
| Dominant (60%) | `Color(.systemBackground)` | #FFFFFF | Main screen background, play area |
| Secondary (30%) | `Color(.secondarySystemBackground)` | #F2F2F7 | Card face background, stats bar background, session summary background |
| Accent (10%) | `.accentColor` / `.tint` (system blue) | #007AFF | See reserved list below |
| Destructive | `Color.red` | #FF3B30 | Incorrect feedback overlay, error count highlight |

### Feedback Colors (Semantic, Non-Accent)

| Color | SwiftUI Token | Usage |
|-------|--------------|-------|
| Correct feedback | `Color.green.opacity(0.85)` | Feedback overlay background for correct decisions |
| Incorrect feedback | `Color.red.opacity(0.85)` | Feedback overlay background for incorrect decisions |
| Suit red | `Color.red` | Hearts and diamonds suit symbols on cards |
| Suit black | `Color.primary` | Clubs and spades suit symbols on cards |
| Card back | `Color.blue.opacity(0.8)` | Face-down card fill |

### Accent Reserved For (Explicit List)

System blue accent is reserved for these elements only:
1. "Start Session" button on the pre-session screen
2. "Play Again" button on the session summary screen
3. "End Session" button/link during active play
4. Navigation bar tint (back buttons, settings icon)
5. Preset picker selection highlight
6. Toggle/picker active states in rule configuration form

Accent is NOT used for: action buttons (Hit/Stand/Double/Split/Surrender), card elements, feedback overlays, stats text, or headings.

### Action Button Colors

Action buttons use a distinct treatment to separate them from navigation and avoid accent overload:

| Button | Background | Text |
|--------|-----------|------|
| Hit | `Color(.systemGray5)` | `Color.primary` |
| Stand | `Color(.systemGray5)` | `Color.primary` |
| Double | `Color(.systemGray5)` | `Color.primary` |
| Split | `Color(.systemGray5)` | `Color.primary` |
| Surrender | `Color(.systemGray5)` | `Color.primary` |

All action buttons use the same neutral style. The user's focus should be on the hand, not on button differentiation. Disabled actions (unavailable per hand state) use `Color(.systemGray3)` background with `Color.secondary` text and are non-interactive.

## Component Inventory

### CardView
- Size: 56pt W x 80pt T
- Corner radius: 8pt
- Face-up: white/systemBackground fill, 1pt `Color.secondary` stroke, centered rank+suit text
- Face-down: `Color.blue.opacity(0.8)` fill, same stroke, no text
- Rank display: A, 2-10, J, Q, K (not blackjack value for face cards)
- Suit display: Unicode filled symbols (heart 2665, diamond 2666, club 2663, spade 2660)

### HandView
- Horizontal row of CardView instances
- 8pt (sm) spacing between cards
- Horizontally centered in play area
- Overlapping layout if 5+ cards: offset each card by 32pt instead of full width

### FeedbackOverlayView
- Full-screen overlay on the play area (not covering stats bar)
- Background: green at 85% opacity (correct) or red at 85% opacity (incorrect)
- Text: white, `.title2.bold()`, centered
- Correct copy: "Correct"
- Incorrect copy: "Incorrect -- Should: [Action]" where Action is capitalized (Hit, Stand, Double, Split, Surrender)
- Animation in: `.easeIn(duration: 0.15)`
- Display duration: 1.0 second
- Animation out: `.easeOut(duration: 0.2)`
- Transition: `.opacity`

### ActionButtonsView
- Horizontal row of available action buttons
- 16pt (md) spacing between buttons
- Each button: minimum 44pt height, horizontally expanding, rounded rectangle (8pt corner radius)
- Labels: "Hit", "Stand", "Double", "Split", "Surrender"
- Only shows buttons for currently available actions (per `canDouble`, `canSplit`, `canSurrender`)
- Disabled state: grayed out, non-interactive

### StatsBarView (D-09)
- Single horizontal line: "87% . 24 hands . 3 errors"
- Font: `.subheadline` weight regular
- Background: `Color(.secondarySystemBackground)` with 8pt vertical padding
- Positioned at top of play area, below navigation bar
- Always visible during active session
- Dot separator between stats (middle dot character)

### SessionStartView (D-08)
- Vertical form layout
- Mode picker: segmented control (Learn / Test)
- Preset picker: "Vegas Strip" / "Downtown Vegas" / "Custom" as a Picker or segmented control
- Rule summary: read-only display of current rule set with "Edit Rules" link to RuleConfigView
- Primary CTA: "Start Session" button (accent color, prominent style)
- Navigation: pushed onto NavigationStack or presented as the initial view in the Practice tab

### SessionSummaryView (D-10)
- Replaces play area inline (NOT a modal/sheet)
- Vertical layout with sections:
  1. **Heading:** "Session Complete"
  2. **Stats grid:** Hands Played, Accuracy %, Errors, Best Streak -- 2x2 grid of labeled values
  3. **Mistake Log:** scrollable list of errors, each row: "Soft 18 vs 9 -- Hit . Correct: Stand"
  4. **Actions:** "Play Again" (accent, prominent) + "Home" (secondary style)
- Background: `Color(.secondarySystemBackground)` for stat cards

### RuleConfigView (D-13)
- SwiftUI `Form` in a sheet or pushed view
- Sections: Deck Count (picker), Dealer Rules (S17/H17 toggle), Blackjack Payout (picker), Player Options (DAS, RSA, surrender toggles/pickers), Double Restrictions (picker)
- Standard iOS form styling -- no custom styling needed
- "Done" / dismiss button in navigation bar

## Screen Layout

### TrainerView (Main Play Screen)

```
+----------------------------------+
| [< Back]   Practice   [gear]    |  <- Navigation bar
+----------------------------------+
| 87% . 24 hands . 3 errors       |  <- StatsBarView (D-09)
+----------------------------------+
|                                  |
|         [?] [7{club}]           |  <- Dealer hand (face-down + upcard)
|                                  |
|            24pt gap              |
|                                  |
|      [A{heart}] [7{spade}]      |  <- Player hand
|         Total: 18               |  <- Hand total label
|                                  |
|            24pt gap              |
|                                  |
| [Hit] [Stand] [Double] [Surr]   |  <- ActionButtonsView
|                                  |
|          [End Session]           |  <- Text button, accent color
+----------------------------------+
```

### Learn Mode Addition
- In Learn mode (D-05): a label appears above the action buttons: "Correct play: Stand" in `.subheadline` weight bold, `Color.secondary`
- The user still taps an action button to confirm they understand, but the correct answer is pre-revealed

### Feedback State
- FeedbackOverlayView covers the area from below StatsBarView to above "End Session" button
- Cards and action buttons are visible but dimmed underneath the overlay
- After 1 second, overlay fades and phase transitions to play-out

### Play-Out State (D-05)
- Dealer hole card flips face-up (no animation in Phase 2 -- just reveals; card flip animation is nice-to-have)
- Dealer draws additional cards with 0.3s delay between each
- Result label appears centered: "Win", "Loss", or "Push" in `.title2.bold()`
- Result visible for 1.0 second, then auto-advances to next hand

## Interaction Contracts

### Game Loop State Machine

| State | User Can Do | System Does | Next State |
|-------|------------|-------------|------------|
| preSession | Select mode, select preset, edit rules, tap "Start Session" | Show SessionStartView | dealing |
| dealing | Nothing (brief, <0.5s) | Deal 2 cards each to player and dealer, check for player blackjack | awaitingDecision (or showingResult if BJ) |
| awaitingDecision | Tap Hit / Stand / Double / Split / Surrender | Show available actions, show learn mode hint if applicable | showingFeedback |
| showingFeedback | Nothing (auto-advances after 1s) | Show FeedbackOverlayView, record decision, update stats | playingOut (or awaitingDecision if hand continues after hit) |
| playingOut | Nothing (auto-advances) | Dealer reveals hole card, draws to completion | showingResult |
| showingResult | Nothing (auto-advances after 1s) | Show Win/Loss/Push label | dealing (next hand) |
| sessionSummary | Tap "Play Again" or "Home" | Show SessionSummaryView, persist session to SwiftData | preSession (or app home) |

### Edge Cases

| Scenario | Behavior |
|----------|----------|
| Player busts | Skip dealer play-out, show "Bust" result immediately |
| Player surrenders | Skip play-out, show "Surrender (-0.5)" result |
| Player doubles | Deal one card, then proceed to dealer play-out |
| Player splits | Play each split hand sequentially (same feedback loop per hand) |
| Player blackjack | Show "Blackjack!" result, skip decision phase |
| Dealer blackjack (peek) | If American peek rules: hand ends immediately, show result |
| Shoe needs reshuffle | Reshuffle between hands, show informational message briefly |
| Player taps "End Session" | Confirmation alert, then transition to sessionSummary |
| App backgrounded mid-session | Session state preserved in ViewModel (in-memory); not persisted until "End Session" |

### Haptic Feedback

| Event | Haptic Type |
|-------|-------------|
| Correct decision | `.success` (UINotificationFeedbackGenerator) |
| Incorrect decision | `.error` (UINotificationFeedbackGenerator) |
| Deal cards | `.light` (UIImpactFeedbackGenerator) |
| Session complete | `.medium` (UIImpactFeedbackGenerator) |

|-------|-----------|---------|

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Dynamic Type | All text uses SwiftUI text styles (`.body`, `.subheadline`, `.title2`). Sizes scale automatically. |
| VoiceOver | Card labels: "Ace of Hearts", not "A heart-symbol". Action buttons labeled with full action names. Feedback announced via `AccessibilityNotification.Announcement`. |
| Color contrast | System semantic colors meet WCAG AA by default in both light and dark mode. Feedback overlays use white text on colored backgrounds at 85% opacity -- sufficient contrast. |
| Reduce Motion | If `AccessibilitySettings.isReduceMotionEnabled`, skip feedback overlay animation (show/hide instantly, keep 1s display time). |
| Touch targets | All interactive elements minimum 44pt x 44pt per Apple HIG. |

## Dark Mode Contract

All colors use SwiftUI semantic tokens (`Color(.systemBackground)`, `Color(.secondarySystemBackground)`, `Color.primary`, `Color.secondary`). These automatically adapt to dark mode. No manual dark mode palette needed.

| Element | Light Mode | Dark Mode (automatic) |
|---------|-----------|----------------------|
| Background | White | Black |
| Card face | White | Dark gray |
| Card back | Blue 80% | Blue 80% (same) |
| Card text | Black (primary) | White (primary) |
| Red suits | Red | Red (same) |
| Stats bar bg | Light gray | Dark gray |
| Feedback overlays | Green/Red 85% | Green/Red 85% (same) |
| Action buttons | System gray 5 | System gray 5 (adapts) |
