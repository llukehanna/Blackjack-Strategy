<decisions>
## Implementation Decisions

### Color System
- **D-01:** Accent color: custom dark slate (~#1C2B3A, adaptive for dark mode: near-white or light slate inverse). Used for all interactive primary elements — primary action buttons, links, selected states.
- **D-02:** All backgrounds and text use system adaptive colors: `.systemBackground`, `.secondarySystemBackground`, `.systemGroupedBackground`, `.primary`, `.secondary`. No custom colors for backgrounds or text.
- **D-03:** Semantic feedback colors: correct = `.green` (system), incorrect = `.red` (system). These are already in place; maintain them.
- **D-04:** Define a `BJSColors` or `DesignTokens` namespace in Swift constants (not an asset catalog) to reference the accent and any named colors. This ensures they're referenceable as typed constants throughout the app.

### Spacing System
- **D-05:** Spacing scale: 4 / 8 / 12 / 16 / 24 / 32pt. Define as Swift constants (e.g., `Spacing.xs = 4`, `Spacing.sm = 8`, `Spacing.md = 16`, `Spacing.lg = 24`, `Spacing.xl = 32`). All padding, spacing, and insets in views must reference these constants — no raw literals.

### Typography System
- **D-06:** Typography hierarchy:
  - `title`: `.title2.bold()` — screen headings, session-complete header
  - `section`: `.subheadline` + `.foregroundStyle(.secondary)` — section labels (Mode, Preset, Rules)
  - `body`: `.body` — primary content text
  - `secondary`: `.subheadline` + `.foregroundStyle(.secondary)` — supporting/descriptive text
  - `mono`: `.title2.monospaced().bold()` — card rank+suit display (already in CardView)
  - Define as a `Typography` enum or extension with static properties if repeated more than twice.

### Layout / Safe Area
- **D-07:** Fix tab bar overlap: all screens inside TabView must use `.ignoresSafeArea(.container, edges: [])` appropriately, or ensure bottom content has `.safeAreaInset` padding. The tab bar must not clip action buttons or "End Session" button.
- **D-08:** TrainerView play area: the action buttons and "End Session" button at the bottom must clear the tab bar safe area. Use `.safeAreaInset(edge: .bottom)` or explicit `.padding(.bottom, safeAreaBottomInset)` rather than fixed values.
- **D-09:** All screens must be tested in both standard and SE-sized iPhones (tight vertical) to confirm no overflow or clipping.

### Header / Navigation
- **D-10:** TrainerView: keep native NavigationBar with inline title "Practice" and gear `ToolbarItem`. Below the nav bar, redesign `StatsBarView` into a clean, intentional element with visual weight — not a plain text string. Styling is Claude's discretion within the "clean, analytical" constraint (e.g., a thin separator + styled stat chips, or a compact horizontal stack with icons).
- **D-11:** SessionStartView: remove the "Ready to Practice" title and subtitle from inside the scroll view. The NavigationBar title "Practice" is sufficient. Content starts directly with the Mode section. This removes the redundant double-title.

### Action Button Style
- **D-12:** Primary actions (Hit, Stand): filled background using the custom dark slate accent color, white label. These are the two most-used actions and get visual prominence.
- **D-13:** Secondary actions (Double, Split, Surrender): outlined or gray fill (system gray), primary-colored label. Distinct from primary but not de-emphasized so much that they're hard to tap.
- **D-14:** All action buttons maintain `minHeight: 44` for touch targets (already in place — keep it).
- **D-15:** "End Session" button: use `.buttonStyle(.bordered)` with a subdued/secondary appearance. Not primary weight — it interrupts training flow.

### Card Visual
- **D-16:** Card size stays at 56×80pt. Size is sufficient for the current layout.
- **D-17:** Add a subtle drop shadow to face-up cards: ~2pt Y-offset, 4pt blur radius, 10–15% opacity black. Face-down cards keep their blue fill without shadow or with a matching subtle shadow. Gives cards physical depth.
- **D-18:** Card corner radius stays at 8pt (already in place).

### Reusable Component Targets
- **D-19:** Extract or refine these reusable components as part of this phase:
  - `StatsBarView` — redesign in place, keep as a reusable component
  - `CardView` — add shadow, keep as reusable
  - `ActionButtonsView` — update to primary/secondary split, keep as reusable
  - `SectionContainerView` or a view modifier for consistent section padding/background (to eliminate scattered `.padding(.horizontal, 16)` and `Divider()` patterns in SessionStartView)
  - `StatCardView` — the 2×2 grid cell in SessionSummaryView; refine styling and extract if needed
- **D-20:** Do NOT create a design system file that isn't immediately used. Only extract components used in 2+ places or where the complexity justifies it.

### Verification Requirements
- **D-21:** Verification MUST include screenshots of all 3 main screens: SessionStartView, TrainerView (play state), SessionSummaryView. Visual review is required — functional tests alone are not sufficient.
- **D-22:** Explicit confirmation required: (a) no tab bar overlap anywhere, (b) spacing is consistent with the defined scale, (c) layout looks production-ready in both light and dark mode.

### Claude's Discretion
- Exact shade/lightness of the dark slate accent for dark mode inverse (should lighten to remain legible, e.g., light slate or off-white)
- StatsBarView exact design — text chips, divider line, icons, or pure typography treatment — within the "clean, analytical" constraint
- Whether `Typography` and `Spacing` are enums, structs, or extension constants — choose whatever is idiomatic in this codebase
- SessionSummaryView background: currently `secondarySystemBackground` while TrainerView uses `systemBackground` — unify if there's a visual inconsistency
