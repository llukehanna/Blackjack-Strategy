## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Swift Constant | Usage |
|-------|-------|----------------|-------|
| xs | 4pt | `Spacing.xs` | Icon gaps, inline padding, tight internal element gaps |
| sm | 8pt | `Spacing.sm` | Compact element spacing (card gaps in HandView, inner VStack spacing) |
| smd | 12pt | `Spacing.smd` | Intermediate spacing (button stack gaps, section internal vertical rhythm) |
| md | 16pt | `Spacing.md` | Default element spacing, horizontal screen insets, grid gaps |
| lg | 24pt | `Spacing.lg` | Section vertical padding, major content separators, Spacer(minLength:) in play area |
| xl | 32pt | `Spacing.xl` | Layout-level gaps, generous section breaks |

Source: CONTEXT.md D-05 (user-specified scale: 4/8/12/16/24/32).

Exceptions:
- Touch target minimum height: 44pt (per D-14, Apple HIG). This is a component constraint, not a spacing token.
- Card size: 56x80pt (per D-16). Fixed component dimension, not spacing.

## Typography

All roles use the system San Francisco font via SwiftUI dynamic type styles. Define as `Typography` enum or extension with static properties (per D-06).

| Role | SwiftUI Style | Weight | Usage |
|------|---------------|--------|-------|
| title | `.title2` | `.bold()` | Screen headings ("Session Complete"), major section headers |
| section | `.subheadline` | regular | Section labels ("Mode", "Casino Preset", "Rules"), used with `.foregroundStyle(.secondary)` |
| body | `.body` | regular | Primary content text, rules summary, mistake log entries |
| secondary | `.subheadline` | regular | Supporting/descriptive text, stat labels, player total. Always paired with `.foregroundStyle(.secondary)` |
| mono | `.title2.monospaced()` | `.bold()` | Card rank+suit display in CardView only |
| buttonLabel | `.body` | `.bold()` | Action button labels (Hit, Stand, Double, Split, Surrender) |

Source: CONTEXT.md D-06.

Line height: System defaults (SwiftUI manages line height automatically with dynamic type). No custom lineSpacing overrides.

## Color

This app uses iOS system adaptive colors for all backgrounds and text (per D-02). The only custom color is the accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `.systemBackground` (system adaptive) | Primary screen backgrounds (TrainerView, SessionStartView scroll content) |
| Secondary (30%) | `.secondarySystemBackground` / `.systemGroupedBackground` (system adaptive) | Cards/containers (stat cards, StatsBarView background, section containers) |
| Accent (10%) | Custom dark slate `#1C2B3A` light mode / light slate inverse dark mode | See reserved-for list below |
| Correct feedback | `.green` (system) | Correct decision overlay background |
| Incorrect feedback | `.red` (system) | Incorrect decision overlay background, destructive button roles |

### Accent Reserved For

The custom dark slate accent color is used ONLY on these elements:

1. **Primary action buttons** (Hit, Stand) — filled background with white label (D-12)
2. **"Start Session" CTA** — `.buttonStyle(.borderedProminent)` tinted to accent
3. **"Play Again" CTA** — `.buttonStyle(.borderedProminent)` tinted to accent
4. **"Edit Rules" link** — text link color
5. **Selected segmented control segments** — tint color on Picker
6. **Navigation bar gear icon** — toolbar item tint

Source: CONTEXT.md D-01, D-02, D-03.

### Custom Color Definition

Define in `BJSColors` or `DesignTokens` namespace as Swift constants (D-04):

| Name | Light Mode | Dark Mode | Notes |
|------|-----------|-----------|-------|
| `accent` | `#1C2B3A` (dark slate) | `#D1D9E0` (light slate) | Primary interactive elements. Must pass WCAG AA contrast on both system backgrounds. |

Dark mode inverse: light slate `#D1D9E0` provides sufficient contrast on dark system backgrounds while maintaining the slate tone family.

### Background Normalization

Unify background usage across screens (per Claude's discretion note in CONTEXT.md):

| Screen | Background | Rationale |
|--------|-----------|-----------|
| SessionStartView | `.systemGroupedBackground` | Grouped content with distinct sections |
| TrainerView | `.systemBackground` | Clean play area, cards need contrast |
| SessionSummaryView | `.systemGroupedBackground` | Grouped content with stat cards. Changed from `.secondarySystemBackground` to match SessionStartView pattern. |
| Stat cards (in SessionSummaryView) | `.secondarySystemBackground` | Cards float above grouped background |

|-----------|---------|
| `SectionContainerView` (or ViewModifier) | Consistent section padding and background for SessionStartView sections. Eliminates repeated `.padding(.horizontal, 16)` + `Divider()` pattern. Applies `Spacing.md` horizontal inset, `Spacing.md` vertical padding. |

### StatsBarView Redesign

Current: single line of text on `secondarySystemBackground`.

New design (Claude's discretion, "clean, analytical" constraint):

- Horizontal `HStack` of 3 stat chips separated by thin vertical dividers (`Divider()` rotated or custom 1pt separator)
- Each chip: value (`.body.bold()`, primary color) above label (`.caption`, secondary color)
- Chips: "92%" / Accuracy | "14" / Hands | "1" / Errors
- Full-width bar with `Spacing.sm` vertical padding
- Background: `Color(.secondarySystemBackground)` with 0.5pt bottom separator line
- No icons — pure typography treatment for maximum information density

## Layout Contracts

### Safe Area / Tab Bar Fix (D-07, D-08)

The tab bar currently clips action buttons and "End Session" in TrainerView. Fix approach:

- TrainerView `playArea`: add `.safeAreaInset(edge: .bottom)` or ensure the bottom `Spacer` accounts for tab bar height
- All screens inside TabView must not have content clipped by the tab bar
- Verify on both standard iPhone (e.g., iPhone 15) and SE-sized iPhone (tight vertical space) (D-09)

### Screen Layout Specifications

**SessionStartView:**
- Remove header VStack ("Ready to Practice" + subtitle) entirely (D-11)
- Content begins directly with Mode section
- Each section: `SectionContainerView` wrapping content with `Spacing.md` horizontal inset, `Spacing.md` vertical padding
- Section dividers: thin system `Divider()` between sections
- "Start Session" CTA: `.buttonStyle(.borderedProminent)`, full-width, `Spacing.lg` vertical padding above and below
- Background: `.systemGroupedBackground`

**TrainerView:**
- Navigation bar: inline title "Practice", trailing gear `ToolbarItem` (D-10)
- Below nav bar: redesigned `StatsBarView`
- Play area: `VStack(spacing: 0)` with `Spacer(minLength: Spacing.lg)` between dealer hand, player hand, and action buttons
- Action buttons: primary/secondary split (D-12, D-13)
- "End Session": `.buttonStyle(.bordered)`, subdued/secondary appearance (D-15), `Spacing.md` top padding
- Bottom safe area clearance for tab bar
- Background: `.systemBackground`

**SessionSummaryView:**
- Heading: "Session Complete" using `Typography.title`, `Spacing.lg` top padding
- Stats grid: 2x2 `LazyVGrid`, `Spacing.md` gap, `Spacing.md` horizontal inset
- Stat cards: value in `Typography.title` + label in `Typography.secondary`, `Spacing.md` vertical padding, 8pt corner radius, `.secondarySystemBackground` fill
- Mistake log: left-aligned, `Typography.section` heading, `Typography.body` entries
- Actions: "Play Again" (`.borderedProminent`) + "Home" (`.bordered`), `Spacing.smd` gap, `Spacing.md` horizontal inset
- Background: `.systemGroupedBackground`

### Card Visual (D-16, D-17, D-18)

| Property | Value |
|----------|-------|
| Size | 56 x 80pt |
| Corner radius | 8pt |
| Face-up background | `.systemBackground` |
| Face-up border | `Color.secondary`, 1pt stroke |
| Face-up shadow | Y-offset: 2pt, blur: 4pt, color: `Color.black.opacity(0.12)` |
| Face-down fill | `Color.blue.opacity(0.8)` |
| Face-down shadow | Same subtle shadow as face-up (visual consistency) |
| Text | Rank+suit, `Typography.mono`, suit-colored (red for hearts/diamonds, primary for clubs/spades) |
